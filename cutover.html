OMS/WMS 2.0 — 배포·컷오버 전략 (v2 · 2차원 반복 배포 — 민철 확정 모델 · SSD-4967)

스키마 v12 · 아키텍처 · 창고는 못 멈춘다 — 전 과정 무중단 전제
🔑 배포는 2차원으로 반복(iterative)한다 (민철 확정) — 세로축 = 도메인(이벤트 → 트래킹 → 작업문서 → 주문 → 재고·예약), 가로축 = 단계(① 섀도: V2에 그림자 기록하며 오류 관찰 → ② 읽기 primary 전환: V2가 primary, V1은 자동 폴백 → ③ 쓰기 primary 전환: 완전 이관). 각 도메인이 독립적으로 ①→②→③ 사다리를 오르므로 빅뱅이 없다 — 항상 "한 도메인의 한 칸"만 전진하고, 어느 칸이든 한 칸 뒤로 되돌릴 수 있다. 유일한 특수 칸 = 재고·예약의 ③(전역 불변식이라 도메인 내부를 더 못 쪼갬 → 실사날 런북으로 처리). V1·V2가 같은 internal-api 프로세스라 칸 전진은 배포가 아니라 설정 플래그다.

배포 매트릭스 — 도메인 × 단계 (칸 클릭 = 상세)

① 섀도
V2 그림자 기록 · 오류 관찰		② 읽기 primary = V2
V1 자동 폴백		③ 쓰기 primary = V2
완전 이관
사용법 — 칸을 클릭하면 그 도메인·단계에서 정확히 뭘 하는지, 전진 조건과 롤백 방법이 나옵니다. 도메인은 위(저위험)부터 아래(코어) 순으로 착수 — 단, 각 행은 독립이라 앞 행이 ③까지 가길 기다릴 필요 없음.

단계별 데이터 흐름 — 한 도메인이 사다리를 오를 때

→ →
쓰기 (authority) 섀도 쓰기 (best-effort) 읽기 primary 읽기 폴백 역방향 dual-write (롤백 대비) 드리프트 대사

특수 칸: 재고·예약 ③ — 실사날 밤 런북

왜 이 칸만 특수한가: 가용성 = 전체 재고 − 전체 예약이라 도메인 내부를 주문 절반/절반으로 못 쪼갬(쪼개면 어느 쪽도 가용성 계산 불가 → oversell). 그래서 이 한 칸만 원자적 플립 — 대신 되돌릴 수 있게 만든다.
1. 출고 동결
마감 후 야간 — 창고 작업 없는 시간대. 주문 유입은 계속
2. 실사 (実査)
물리 카운트 — V2 원장의 기초잔고. "장부 이관"이 아니라 "실물 기준 재출발"
3. 기초잔고 시드
실사 결과 → stock_movement 개시 행 + 활성 예약 V1→V2 변환(검증 리포트 통과 필수)
4. 플립
재고 authority 플래그 V1→V2. 배포 아님 — 설정 스위치 한 번
5. 검증 출고
아침 첫 배치 소량 — 원장·예약·라벨·WC push 전 구간 확인
6. 관찰 2주
역방향 dual-write(V2→V1) 유지 — 문제 시 플래그 원복으로 즉시 롤백

칸 전진 게이트 — "fine해 보이면"을 수치로

체크 (도메인별 일일 드리프트 리포트)내용
①→② 전진해당 도메인 섀도 드리프트 0건 연속 7일 + 섀도 쓰기 오류율 관찰 완료
②→③ 전진폴백 발동률 ~0(V2 읽기가 V1 폴백 없이 자립) + 화면 정합 이슈 0
③ 후 청산역방향 dual-write 2주 green → 해당 도메인 V1 경로 제거. 전 도메인 ③ 완료 시 DDB·BQ 리드모델 폐기

마이그레이션 변환 규칙(M1~M6)은 스키마 페이지 행동 규칙 계약 참조 — 섀도 라이터가 곧 마이그레이션 도구라서, 각 도메인의 ① 기간이 곧 매핑 코드의 프로덕션 실전 검증 기간이다.
