✅ 수용 (둘 다 또는 근거 확실)

reservation 부활[둘 다] 라인 컬럼 예약은 복수 로케이션 분할 불가 + "원장이 진실"인데 reserved는 라인에서 읽는 SoT 모순. 원장에서 RESERVE/RELEASE 타입 제거 — 원장은 물리 이동만, 예약은 이 테이블이 진실
stock_balance (matview 폐기)[둘 다] matview는 refresh 전 스캔분이 안 보임(read-your-writes 붕괴). 원장과 같은 트랜잭션에서 upsert되는 프로젝션 테이블로
ops_session_line 승격[둘 다] 입고 수령 jsonb 증분 = 동시 스캐너에서 silent lost-update + 트래킹이 jsonb 원소 참조 불가. UNIQUE(session, box_seq)로 마감 중복도 DB 차단
wc_sync_outbox 재분리[둘 다] 지워도 되는 스캔 로그와 절대 잃으면 안 되는 동기화 큐는 보존 정책 상극
product_ref 부활 (얇게)[둘 다] 주문 없는 재고 스캔이 매번 원격 카탈로그 호출 = 카탈로그 장애가 창고 정지, sku 오타 = 유령 재고, Variant 해석이 재고 경계에 없음 = SSD-2780 재발
order_audit 신설[둘 다] V1 실존 기능(21 operation × 10 source + 전용 API)이 v5에 무주택 = 기능 회귀. hold 이력·시스템 이벤트도 여기로
tracking_event 신설[Claude] unified_status 단일값 덮어쓰기는 배송 성능(구간별 소요) 계산 불가 + Deleo 국내/국제 leg 상관키 자리 없음. 라벨 재출력 감사도 여기
mention 신설 (소형)[둘 다] 안읽음 배지가 전 주문 jsonb 스캔 + 읽음 처리가 주문 row version 충돌. 소형 테이블 + (user, read_at) 인덱스로 O(1)
원장 보강[둘 다] occurred_at 전 테이블 명시 · INBOUND/RETURN_RESTOCK 행에 unit_cost 직접 기록(phase-2 FIFO 대비) · lot_id/expiry nullable 자리(V1 WMS가 이미 lotCd/expDate 제공) · 멱등키 파생 규칙(취소 후 정당 재실행 = 새 generation, V1 requiresUniqueTimelineKey 계승) · JIT_COMMITTED→ON_HAND 전환은 입고와 같은 트랜잭션(순간 oversell 창 차단)

🔄 v7 통합 (민철 챌린지 2026-07-26)

event_log + order_audit + tracking_event + mention→ event 하나 — 넷 다 [누가·언제·무엇에·무슨 일] 동형 append 로그라 kind(SCAN/ORDER_OP/TRACKING/MENTION)로 통합. kind별 partial index로 배지·워크리스트 O(1) 유지, 월 파티션 + kind별 보존정책(스캔 prune, 감사 영구). Claude Critic C3의 대안 경로와 일치
